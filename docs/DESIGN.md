# 基金日记 · 数据库与实验机制设计

> 版本 v2.0 设计稿 · 2026-10-06
> 目标：验证「我」能否持续预测 5 只持仓基金的单日涨跌，并证明是否优于简单基准。
> 最终预测由用户填写；系统负责准备数据、检查依据、锁定、评分、复盘、统计信号、回测规则。AI 草稿只作参考，单独计分。

---

## 1. 总体架构

```
GitHub 仓库 = 数据库（JSON 文件） + 审计日志（git 提交历史，不可篡改）
GitHub Actions = 定时任务（抓数据、算信号、出草稿、评分、复盘、回测）
GitHub Pages = 手机 App（三个标签页：预测 / 成绩 / 实验室）
```

- **读**：App 直接读取仓库里的 JSON 文件。
- **写**：用户在 App 里提交预测时，通过 GitHub API 往仓库提交一个新文件。需要一次性配置一个只对本仓库有写权限的令牌，保存在手机浏览器里。
- **锁定的证据**：以 git 提交时间为准，由 GitHub 服务器记录，事后无法篡改。预测文件「只能新建、不能覆盖」：同名文件已存在时，API 会拒绝写入。

### 2.3 市场数据快照（时点纪律的核心）
每一条数据都带四个时间字段：
```json
{ "id": "NDX@2026-10-07", "name": "纳斯达克100", "value": 0.87, "unit": "%",
  "source": "Yahoo Finance",
  "dataTime": "2026-10-07T16:00:00-04:00",
  "cutoff":   "2026-10-08T04:00:00+08:00",
  "fetchedAt":"2026-10-08T08:07:12+08:00",
  "availableAtLock": true }
```
- `dataTime`：数据本身对应的时间（例如美股收盘时间）。
- `cutoff`：这条数据在北京时间什么时候可以拿到。
- `fetchedAt`：系统实际抓取的时间。
- `availableAtLock`：在当天预测锁定时是否已经可以获得。锁定后才回填。

每天两个批次：`evening`（前一晚 22:13）和 `morning`（当天 08:07，美股已收盘）。快照文件一旦提交就不再修改。

### 2.4 信号定义表 `signals.json`
```json
{ "id": "R017", "name": "纳斯达克隔夜涨幅 > +1%",
  "sourceType": "行情",            // 行情 / 板块 / 资金 / 消息 / 外部观点 / 日历
  "scope": "*",                    // * 或基金代码
  "when": "ndx_on > 1",            // 只能引用快照里的变量
  "vote": 1,                       // +1 看涨 / -1 看跌
  "status": "实验中",              // 实验中 / 待验证 / 有效 / 失效 / 淘汰
  "createdAt": "2026-10-06", "statusHistory": [ { "date": "...", "from": "...", "to": "...", "why": "..." } ] }
```
外部观点（如某位博主的立场）统一用 `sourceType: "外部观点"` 记录，前台不单独展示。

### 2.5 每日信号触发表 `triggers/{日期}.json`
```json
{ "date": "2026-10-08", "batch": "morning", "snapshot": "2026-10-08/morning",
  "funds": { "024481": [ { "signal": "R017", "triggered": true, "inputs": { "ndx_on": 0.87 } } ] } }
```
「今天触发」只看这张表，与历史成绩无关。

### 2.6 预测快照 `predictions/{日期}/{预测方}.json`
预测方：`user`（你，正式成绩）、`ai`（AI 草稿，对照组）、`model`（规则模型）、`bench_us`、`bench_prev`、`bench_zero`（三个基准）。
```json

  "createdAt": "2026-10-08T08:35:00+08:00",
  "lockedAt":  "2026-10-08T08:35:04+08:00",     // 以 git 提交时间为准
  "snapshot": "2026-10-08/morning", "dataCutoff": "2026-10-08T08:07:12+08:00",
  "modelVersion": "v1.0",
  "overall": { "value": 0.68, "conclusion": "..." },
  "funds": {
    "024481": { "value": 0.80,
      "reasons": [ { "text": "纳指隔夜 +0.87%，科技外部信号偏正", "signals": [], "dataRefs": ["NDX@2026-10-07"] },

      "conclusion": "温和上涨" } } }
```
每只基金只有一个 `value`，没有区间和概率。

## 3. 每日流程（时间线）

| 时间（北京） | 动作 | 写入 |
|---|---|---|
| T-1 22:13 | 抓数据 → 晚间快照 → 算信号触发 → 规则模型、三个基准、AI 草稿各出一版 | snapshots / triggers / predictions(ai, model, bench_*) |
| T 08:07 | 补抓隔夜美股收盘 → 早间快照 → 重算触发 → 基准与 AI 草稿出**早间版**（晚间版保留） | 同上（新文件，不覆盖） |
| T 08:07–09:25 | 你在 App 里参考数据和草稿，填写 5 个数值和理由，提交后立即锁定 | predictions(user) |
| T 09:25 | 截止。之后提交的预测标记为「迟交」，不计入正式成绩 | — |
| T 盘中及之后 | 可以追加修正意见 | amendments |
| T 21:00–23:00 | 抓净值 → 评分 → 复盘 → 更新信号统计和状态 → 规则模型升级门槛 | results / reviews / signals / models / stats |

当天没有提交预测的，记为「缺席」：你的成绩不计这一天，基准和 AI 草稿照常计分。

## 4. 核心实验机制

### 4.1 时点纪律（防止事后解释）
1. 快照只收 `cutoff ≤ 快照时间` 的数据；预测页只展示快照里的数据。
2. 你的每条理由可以关联数据或信号。提交时，系统检查被引用的数据 `cutoff` 是否早于提交时间。
3. 复盘时，AI 逐条检查自由文字理由里有没有锁定后才出现的信息（例如盘中走势），命中的标记「疑似事后信息」。

### 4.2 依据检查（提交前提示，不阻止提交）
每条引用了规律的理由，提交前自动判定为三类：
- ✅ **有效依据**：历史有效（状态为「有效」）并且今天触发。
- ⚠️ **今天未触发**：历史有效，但今天条件不满足。
- ❌ **历史不成立**：状态不是「有效」，或历史命中率低于基准。

判定结果随预测一起锁定。以后可以统计：带 ⚠️/❌ 依据的预测，是不是更不准。

### 4.3 方向判定（统一处理接近 0 的情况）
- 三态：涨（> +0.10%）、跌（< −0.10%）、平（−0.10% ~ +0.10%），预测值和实际值用同一阈值。
- 命中＝预测三态与实际三态相同。
- 阈值 0.10% 写在配置里，修改要记录版本。

### 4.4 评分指标
| 指标 | 定义 |
|---|---|
| 方向命中率 | 命中次数 / 判断次数 |
| MAE | |预测 − 实际| 的平均，单位百分点 |
| 相对基准提升 | 命中率差（百分点），MAE 改善率 =（基准 MAE − 我的 MAE）/ 基准 MAE |
| 显著性 | 与最好的基准做配对比较：同一天同一只基金逐条比误差，自助法（bootstrap）给出 MAE 差的 95% 区间；区间不跨 0 才算「真正超过」 |

成绩页回答的问题：**我的预测是否在命中率和 MAE 上都显著优于最好的基准？** 样本少于 100 条时只显示数字，不下结论。

### 4.5 三个基准（每天自动预测，和你同场计分）
| 基准 | 预测值 |
|---|---|
| 跟随外盘 | β × 隔夜外盘涨跌（QDII 用纳指100，其余用费城半导体）。β 在研究集上拟合，随规则版本冻结 |
| 昨日延续 | 该基金上一个交易日的实际涨跌幅 |
| 永远 0% | 0（只看 MAE，方向恒为「平」） |

另有两个对照组：规则模型、AI 草稿。

### 4.6 信号统计与状态机
每个信号在「触发」样本上统计：样本数、实际上涨/下跌次数、方向命中率、MAE（以触发时的历史平均涨跌作为预测值）、同期基准命中率（全部样本中实际与投票方向一致的比例），以及 Wilson 95% 区间。

```
实验中 ──样本≥20──▶ 待验证 ──区间下限>基准 且 留出集确认──▶ 有效
   │                   │                                     │
   │                   └──区间上限<基准──▶ 失效 ◀──近40日命中<基准──┘
   └────────────────────────────────────────▶ 失效 ──持续20个交易日──▶ 淘汰
```
- 只有「有效」的信号能成为 ✅ 依据。
- 打脸榜：「最可靠的规律」按区间下限排序，「最会骗人的规律」按区间上限从低到高排序，只列样本 ≥ 20 的。

### 4.7 防过拟合：研究集 / 留出集
- 取最近 200 个交易日：前 160 天为**研究集**，后 40 天为**留出集**。
- AI 提出规则修改时**只能看到研究集的统计**，看不到留出集。
- 升级门槛（三条同时满足才上线）：
  1. 研究集：MAE 不变差超过 0.02 个百分点，命中率不下降超过 1 个百分点；
  2. 留出集：同样的标准；
  3. 留出集上相对最好基准的优势不丢失。
- 不通过的修改也写进变更记录，标记「未上线」。
- 真正的检验是之后的实盘：每个版本单独统计上线后的实盘成绩。

### 4.8 每日复盘（自动生成，可补答）
1. 哪些判断正确
2. 哪些判断错误
3. 贡献最大的信号
4. 误导判断的信号
5. 下次怎么改
6. **反省一：我是不是在找事后理由？** 逐条比对理由引用的数据时间和锁定时间（见 4.1）。
7. **反省二：删掉这条理由，结论还一样吗？** 关联了信号的理由，用规则模型去掉该信号重算，看方向是否改变；纯文字理由由 AI 评估，并留空让你补答。

复盘不修改任何预测，只追加记录。

## 5. 界面（三个标签页，在数据和机制完成后实现）

- **预测**：日期与锁定状态 → 科技仓整体预测 → 五只基金各一个数值。点击进入详情：预测值、实际值、理由、市场依据、触发的规律及历史命中率、复盘。清单页不放规则和数据。
  - 未锁定时：显示数据快照、今日触发的有效规律、AI 草稿（可一键带入再修改），填写 5 个数值和理由 → 依据检查 → 提交锁定。
- **成绩**：结论（是否显著优于基准）→ 我 vs 三个基准 vs AI 草稿 vs 规则模型（命中率、MAE、提升幅度）→ 流水账。
- **实验室**：信号列表（状态、样本、命中率、MAE、基准）→ 打脸榜两张 → 规则版本与变更记录。
